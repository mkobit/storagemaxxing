# Docker Sandbox Composition Report

This report documents the current sandbox composition for `storagemaxxing`, distinguishing between project-required mechanics and optional personal additions as requested.

## 1. Tools and versions required for standalone build/tests

The core toolchain is defined via `mise.toml` and bootstrap processes in `.sbx/kit/spec.yaml`.

- **Bun**: version `1.4.2` (configured in `mise.toml`, `package.json#engines`, and `.sbx/kit/spec.yaml`)
- **Beads**: version `1.2.2` (`gastownhall/beads`, configured in `mise.toml` and `.sbx/kit/spec.yaml`)
- **Mise**: version `2026.8.14` is bootstrapped in `.sbx/kit/spec.yaml`, though `mise.toml` enforces a `min_version = "2026.7.0"`.

## 2. Project-required skills/plugins and their runtime dependencies

The standalone environment (defined in `.sbx/sbxenv.yaml` and `.sbx/sbxenv.agy.yaml`) sets up:

- **Agents**: The environment specifically names `codex` (`.sbx/sbxenv.yaml`) and `agy` (`.sbx/sbxenv.agy.yaml`).
- **Ports**: Both files expose `5173` (Vite frontend) and `6006` (Storybook).
- **Tooling Packages**: `devDependencies` in `package.json` install agent scaffolding (`@fission-ai/openspec`, `modern-web-guidance`).
- **AGY Specific Kit**: `.sbx/sbxenv.agy.yaml` imports a remote kit: `git+https://github.com/shelajev/agy-sbx-kit.git#ref=3e7016f108f3cf09922cf351b55a49e38d97f9f2`.

## 3. Optional personal behavior

- We explicitly support the overlay of personal settings (e.g. `~/.local/share/sbx/personal/personal.sbxenv.yaml` generated by `mkobit/dotfiles`) via CLI concatenation (e.g., `sbx env run .sbx/sbxenv.yaml ~/.local/share/sbx/personal/personal.sbxenv.yaml`).
- The project environment files strictly do _not_ contain these overrides, preserving reproducibility. The core environment validation scripts (`scripts/check-sbx-env.ts`) pass completely independently of this overlay.
- MCPs, native plugins, or global host mappings from `dotfiles` are not activated in the committed source code, nor do we assume their existence in `scripts/check-sbx-env.ts`.

## 4. Duplicated installation mechanics

- `mise` bootstrapping and configuration inside `.sbx/kit/spec.yaml` duplicates some logic that might be formalized in a global pinned kit, particularly:
  ```yaml
  curl -fsSL https://mise.run | MISE_VERSION=v2026.8.14 MISE_INSTALL_PATH=/usr/local/bin/mise sh
  mise use -g bun@1.4.2 && mise use -g github:gastownhall/beads@1.2.2
  ```
- This `.sbx/kit/spec.yaml` could potentially be extracted to a reusable remote kit, similar to the AGY kit.

## Conclusion

The project currently stands standalone. All `bun run lint`, `test`, `typecheck`, and `openspec validate` commands execute successfully on the strict `.sbx/sbxenv.yaml` definition. The environment does not require the personal overlay to function.
